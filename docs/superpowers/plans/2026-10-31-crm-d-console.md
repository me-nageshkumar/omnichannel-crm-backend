> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Segments to the console: a list page, an editor with a catalogue-driven rule builder and a live per-channel-account preview, a "CRM segment" audience in the campaign wizard (with the preview's warnings and the truncated block), the segment column on the Reports campaigns card, and the neutral `CAMPAIGN_SENT` timeline entry.

Segment calls go through `src/app/api/crm.ts`; the campaign wizard changes live in `src/app/Campaigns/NewCampaign/`. No new dependency.

**Tech Stack:** as phases A–C (React 18, TypeScript, PatternFly 6.5, vitest + Testing Library).

## Global Constraints

- Phase A–C Global Constraints apply: CRM code under `src/app/Crm/`, PatternFly tokens only, sentence case, phone width (375 px) on every screen, `apiFetch` + `useLoad`/`useAction`, `React.lazy` page chunk behind `CrmGate`, `useRefetchOnFocus`, `useCrmCan` for authorities.
- **Naming (spec C1):** new code says `channelAccountId`, `ChannelKind`, "channel account", "channel contact"; the only `phoneNumberId` a new file may read is `CrmStatus.phones[].phoneNumberId` when it needs a label for an account id (prefer the preview's own `label`).
- **Rule JSON** exactly as the contract: `{combinator, not, rules}`, `Rule = {field, operator, value: string | string[] | null}`; values are strings (numbers as typed, dates `YYYY-MM-DD`, day counts as integers, booleans `"true"`/`"false"`, `between` a two-element list). Client caps mirror the server: 30 rules, 3 levels, 50 list values, 200 characters, days 1–3650.
- **Operator labels** (`segmentModel.OPERATOR_LABELS`): `is` "is", `isNot` "is not", `contains` "contains", `notContains` "doesn't contain", `startsWith` "starts with", `isSet` "is set", `isNotSet` "is not set", `eq` "equals", `neq` "doesn't equal", `lt` "less than", `lte` "at most", `gt` "more than", `gte` "at least", `between` "between", `before` "before", `after` "after", `withinLastDays` "in the last … days", `moreThanDaysAgo` "more than … days ago", `in` "is any of", `notIn` "is none of", `has` "has", `hasNot` "doesn't have", `hasAny` "has any of", `hasAll` "has all of", `hasNone` "has none of", `isEmpty` "is empty", `isNotEmpty` "is not empty".
- **Value kinds** (`valueKind(type, operator)`): `none` for `isSet isNotSet isEmpty isNotEmpty`; `text` (TEXT); `number` (NUMBER, MONEY; `between` → `numberRange`); `date` / `dateRange` / `days` (DATE by operator); `option` / `options` (PICK, ENUM; `in`/`notIn` → options); `user` / `users` (USER); `company` / `companies` (COMPANY); `boolean`; `label` / `labels` (LABEL); `text` for MULTI `contains`.
- **Preview** (C6, C19): debounced 600 ms after the last change, only when `isComplete(rules)`; the answer for an older tree is dropped (`keyRef` idiom from `FilterBuilderPage`); 400 `INVALID_SEGMENT` field errors land on their rules through `splitErrors`.
- **Counts wording** (C20): "n CRM contacts" plus " (m people)" only when `people !== total`; "first 50,000 only — narrow the rules before sending" when `truncated`.
- Commits: one per task, body ends with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **A user with `crm:view` but not `crm:segments`**: no Segments link, `/crm/segments` shows the permission empty state and makes no segment calls, the wizard shows two radios (Task 1 `withoutSegmentsAuthorityNothingSegmentIsShown`, Task 4 `wizardHidesSegmentRadioWithoutAuthority`).
2. **A saved rule flagged `missing` or `inaccessible`**: shown greyed with its reason, removable, never editable into a bogus field; Save still works after removing it (Task 3 `flaggedRulesAreShownAndRemovable`).
3. **Fast edits during a preview in flight**: the card shows the latest tree's answer only, never an older count (Task 3 `stalePreviewAnswerIsDropped`).
4. **Starting a campaign on a truncated segment**: the Review step says why Start is unavailable; the server's 400 on `audience.segmentId` lands on the audience line (Task 4 `truncatedSegmentBlocksStart`).
5. **Switching the stage rule's pipeline**: the stage value resets and the stage options follow the new pipeline; a stage rule without a pipeline rule in its AND group shows the server's message on that rule (Task 2 `stageOptionsFollowThePipelineRule`).
