# CRM phase D (backend): segments and campaigns — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add saved segments to the CRM module (rule model, allowlisted field catalogue, resolver with set algebra over CRM and channel-contact data, per-caller preview, cached counts with an hourly job, CRUD API behind a new `crm:segments` authority), make a segment a third campaign audience kind in the host (`SEGMENT`, resolved at start for the starting user), feed campaign sends back into CRM timelines as neutral `CAMPAIGN_SENT` entries, add the segment column to the Reports campaigns card, and seed two demo segments.

**Architecture:** New package `crm.segment` in `omnichannel-crm`: `CrmSegment` (document), `SegmentRuleGroup`/`SegmentRule` (the rule tree, same JSON shape as the host's advanced filters), `SegmentFields` (allowlist: keys, value types, operators), `SegmentCatalog` (the per-caller field catalogue), `SegmentValidator` (→ `INVALID_SEGMENT` with `fieldErrors`), `SegmentConditionQueries` (one Mongo query per contact/deal condition, the channel side through a port), `SegmentSets` (pure set algebra), `SegmentResolver` (universe, caps, timeouts → `SegmentMembers`), `SegmentService` (CRUD, counts, preview, in-use check), `SegmentCountRefreshJob`, `SegmentAudienceApi` (the module's public door for the host's campaigns), `CampaignActivityRecorder` (writes `CAMPAIGN_SENT`), `CrmSegmentController`. New ports in `crm.platform` (`ChannelContactQuery`, `BrandDirectory.zoneOf`, `CampaignDirectory.usingSegment`) with adapters in `app.crm`. New ports in `service.campaign` (`SegmentAudiences`, `CampaignObserver`) with adapters in `app.crm` that call the CRM module — the only place the two modules meet.

**Tech Stack:** Java 21, Spring Boot 4.1, Spring Data MongoDB (`MongoTemplate`, `Criteria`, `maxTime`), JUnit 5 + AssertJ + MockMvc, embedded Mongo 7.0.12 in `*IT`.

**Spec:** `docs/superpowers/specs/2026-10-31-crm-segments-campaigns-design.md` (C1–C15, §4, §5, §7). **Depends on:** phases A–C merged into `main` (they are). ## Global Constraints

- Phase A–C Global Constraints apply: module boundary (`crm` imports only `me.nageshk.omnichannel.crm.`, `.common.`, `.security.access.`, `.security.auth.` — `CrmModuleBoundaryTest`; `omnichannel-service` never imports `crm`), every query scoped by `workspaceId` first, errors `{code, message, ...extras}` through `CrmErrors`/`CodedException`, the new collection is `crmSegments` (camelCase; `CrmCollectionsTest`), every new index leads with `workspaceId` (`CrmIndexIsolationIT`).
- **Naming (spec C1):** new code says `channelAccountId`, `ChannelKind`, `ChannelAccount`, "channel contact"; never `phoneNumberId` in a new type, field, method or JSON key. The one mapping place is `crm.segment.ChannelAccounts.of(CrmContact): String` (today `c.getChannel().phoneNumberId()`). Existing phase A–C names are untouched.
- **Rule JSON (C3):** `{"combinator": "and"|"or", "not": boolean, "rules": [rule | group]}`, `rule = {"field", "operator", "value"}`; `value` is a String, a List of Strings, or null — numbers as decimal strings, dates `YYYY-MM-DD`, day counts as integer strings, booleans `"true"`/`"false"`, `between` as a two-element list. Limits: ≤ 30 rules, ≤ 3 group levels (root = 1), ≤ 50 list values, each value ≤ 200 chars, day counts 1–3650.
- **Field keys (C4), exactly:** `contact.lifecycleStatus` PICK, `contact.ownerId` USER, `contact.source` TEXT, `contact.origin.kind` ENUM (`OriginKind`), `contact.companyId` COMPANY, `contact.channelAccountId` PICK (brand channel accounts), `contact.email` TEXT, `contact.jobTitle` TEXT, `contact.creationTime` / `contact.lastActivityAt` / `contact.nextTaskDueAt` DATE, `contact.openDealCount` NUMBER, `contact.openDealAmount` MONEY, `contact.custom:<key>`; `deal.pipelineId` PICK, `deal.stageId` PICK (`dependsOn: deal.pipelineId`), `deal.status` ENUM (OPEN/WON/LOST), `deal.amount` MONEY, `deal.currency` TEXT, `deal.ownerId` USER, `deal.source` PICK, `deal.lostReason` PICK, `deal.daysInStage` NUMBER, `deal.expectedCloseDate` / `deal.closedAt` / `deal.creationTime` DATE, `deal.rotting` BOOLEAN, `deal.custom:<key>`; `channel.label` LABEL, `channel.attribute:<attributeId>` TEXT, `channel.lastMessageAt` DATE, `channel.source` ENUM (CHAT/IMPORT/MANUAL), `channel.doNotContact` BOOLEAN. Custom field → type: TEXT/LONG_TEXT/URL/EMAIL/PHONE → TEXT, NUMBER → NUMBER, CURRENCY → MONEY, BOOLEAN → BOOLEAN, DATE/DATETIME → DATE, SELECT → PICK, MULTI_SELECT → MULTI, USER → USER; inactive fields are not in the catalogue and are `missing` in a saved rule.
- **Operators by type (C4), exactly:** TEXT `is isNot contains notContains startsWith isSet isNotSet`; NUMBER, MONEY `eq neq lt lte gt gte between`; DATE `before after between withinLastDays moreThanDaysAgo isSet isNotSet`; PICK, USER, ENUM, COMPANY `is isNot in notIn isSet isNotSet`; BOOLEAN `is`; LABEL `has hasNot hasAny hasAll hasNone isEmpty isNotEmpty`; MULTI `contains isSet isNotSet`. Negative operators (complement within the universe): `isNot notIn notContains neq hasNot hasNone isNotSet isEmpty` and any group with `not: true`.
- **Builder-check calls (spec C20–C23) bind this plan:** a member is a CRM contact record; `total` counts records, `people` counts distinct `contactId`s, per-account counts sum to `total`; deal rules share one deal only inside AND groups (one query per AND group's deal rules; one query per deal rule in an OR group); `deal.stageId` needs `deal.pipelineId` in the same AND group; a truncated resolution refuses to start a campaign (400 on `audience.segmentId`); a member with no chat on a chosen sender prefers its own channel account when that is a chosen sender.
- **Resolution (C5):** universe = `crmContacts {workspaceId} ∧ ctx.pipelines().criteria("pipelineIds")`; deal conditions of one group = one query on `crmDeals {workspaceId} ∧ ctx.pipelines().criteria("pipelineId") ∧ rules` projecting `primaryCrmContactId`, `crmContactIds`; channel conditions through `ChannelContactQuery.matching` then `crmContacts {workspaceId, contactId in ids}`; every Mongo read `maxTime` 10 s and guarded (503 `SEGMENT_TIMEOUT`); any set over **200,000** ids → 400 `SEGMENT_TOO_BROAD`; members ordered by `crmContactId`, capped at **50,000** with `truncated: true`. Ids are read in chunks of 10,000 (`$in` lists never larger).
- **Dates:** `YYYY-MM-DD` values are read in `BrandDirectory.zoneOf(ws)`: `before d` → `< start of d`; `after d` → `≥ start of the day after d`; `between [a, b]` → `[start of a, start of the day after b)`; `withinLastDays n` → `≥ now − n days`; `moreThanDaysAgo n` → `< now − n days`. `deal.expectedCloseDate` is a `YYYY-MM-DD` string in Mongo: compare lexicographically on the string. `deal.daysInStage gt n` → `stageEnteredAt < now − n days` (and so on, inverted).
- **Errors:** `SegmentErrors.invalid(Map<String,String> fieldErrors)` → 400 `INVALID_SEGMENT` (extras = the map; keys like `name`, `rules[1].rules[0].value`); `tooBroad()` → 400 `SEGMENT_TOO_BROAD`; `nameTaken()` → 409 `SEGMENT_NAME_TAKEN`; `inUse(List<CampaignRef>)` → 409 `SEGMENT_IN_USE` with extra `campaigns` = `"id:name,id:name"`-style is **not** acceptable — `CodedException` extras are `Map<String,String>`, so put the campaign names in `message` ("Used by campaigns: Diwali offer, Spring sale") and ids in extra `campaignIds` (comma-separated); `timeout()` → 503 `SEGMENT_TIMEOUT`.

## Review Focus

1. **A restricted agent previewing a brand-wide segment that names a pipeline they cannot see**: the rule is `inaccessible` and matches nothing; their universe is their pipelines only; NOT groups complement within *their* universe, never the brand's (Task 5 test `restrictedCallerComplementsWithinOwnUniverse`).
2. **A segment used by a running campaign** cannot be deleted; renaming it leaves the campaign's `segmentName` snapshot alone (Task 7 test `runningCampaignBlocksDeleteAndKeepsSnapshot`).
3. **A campaign started by a user who can see fewer contacts than the segment's cached total**: the recipients are the starter's members only, and the segment's `lastSentAt` is still stamped (Task 7 test `campaignResolvesForTheStarter`).
4. **A send to a contact who exists as two CRM contacts (two channel accounts)**: both get a `CAMPAIGN_SENT` entry, neither `lastActivityAt` moves, no deal's rotting clears (Task 7 test `campaignSentWritesTimelineWithoutTouchingActivity`).
5. **Two rules on the same deal field in one group, and deal rules split across two groups**: one group means one deal matches all; two groups mean two possibly different deals (Task 4 test `dealRulesInOneGroupMatchTheSameDeal`).

## Contract for the console (additions to phase A–C's contract)

All under `/api/workspaces/{ws}/crm/segments`, JSON, `crm:view` **and** `crm:segments` (403 without either; 402 when the CRM is off). `rules` is `{combinator: "and"|"or", not: boolean, rules: Array<Rule | Group>}`, `Rule = {field, operator, value: string | string[] | null}`; on GET each rule may also carry `missing: true` or `inaccessible: true`.

| Call | Request | Response |
|---|---|---|
| `GET /` | — | `Segment[]` sorted by name |
| `GET /{id}` | — | `Segment` |
| `POST /` | `{name, description, rules}` | 201 `Segment` |
| `PUT /{id}` | `{name, description, rules, version}` | `Segment`; 409 `VERSION_CONFLICT` |
| `DELETE /{id}` | — | 204; 409 `{code: "SEGMENT_IN_USE", message: "Used by campaigns: …", campaignIds: "id,id"}` |
| `GET /fields` | — | `{groups: Array<{key: "contact"|"deal"|"channel", label, fields: Array<{key, label, type: "TEXT"|"NUMBER"|"MONEY"|"DATE"|"PICK"|"USER"|"ENUM"|"COMPANY"|"BOOLEAN"|"LABEL"|"MULTI", operators: string[], options?: Array<{value, label}>, dependsOn?: string, optionsByParent?: Record<string, Array<{value, label}>>}>}>}` |
| `POST /preview` | `{rules}` | `{total, people, truncated, channelAccounts: Array<{channelAccountId, kind: "WHATSAPP_WEB"|"WHATSAPP_CLOUD"|"INSTAGRAM"|"FACEBOOK"|null, label, count}>}` |
| `POST /{id}/preview` | — | same |

`Segment = {id, name, description, rules, cachedCounts: {total, people, truncated, channelAccounts: Array<{channelAccountId, count}>, at} | null, lastSentAt, lastCampaignId, lastCampaignName, creationTime, lastUpdateTime, version}`.

Errors: 400 `{code: "INVALID_SEGMENT", message, ...fieldErrors as extra keys: "name", "rules[0].rules[1].value", …}`; 400 `SEGMENT_TOO_BROAD`; 409 `SEGMENT_NAME_TAKEN`; 503 `SEGMENT_TIMEOUT`.

Host campaigns: `audience` accepts `{kind: "SEGMENT", segmentId}`; `CampaignView.audience` carries `segmentId`, `segmentName` (null for other kinds); `POST /campaigns/{id}/start` may answer 403 when the caller lacks `crm:view`/`crm:segments`, or 400 `{code: "VALIDATION", field: "audience.segmentId", message}` when the segment is truncated for the caller. Reports: `/reports/campaigns` rows gain `segmentId`, `segmentName`. Activities: new type `CAMPAIGN_SENT` with payload `{campaignId, campaignName, segmentId, segmentName, channelAccountId, channelKind}`; `WHATSAPP_*` activity type names are gone (never emitted).
